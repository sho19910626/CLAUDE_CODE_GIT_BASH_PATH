| ツール | パス | 用途 |
|---|---|---|
| **Insta Studio** | `/` | 企業向け Instagram コンテンツ(フィード / ストーリー / リール)の自動生成 |

# Insta Studio — 企業向け Instagram コンテンツ自動生成

企業HPのURL・企業イメージ・掲載したい文言を入力するだけで、Instagram運用代行に見劣りしないクオリティの投稿コンテンツを自動生成するWebアプリです。

## 生成できるコンテンツ

| コンテンツ | 出力 | 内容 |
|---|---|---|
| **フィード投稿** | PNG (1080×1350 / 4:5) ×4〜8枚 | カルーセル構成(表紙→ポイント解説→CTA) + AI写真背景 + 6種類のテンプレート + キャプション + ハッシュタグ |
| **ストーリー** | PNG + MP4 (1080×1920) | 静止画4種類のテンプレート、および見出し→補足→CTAの3カットで構成する「動くストーリー」(約8秒) |
| **リール動画** | MP4 / H.264 (1080×1920) | 実写映像が主役の1本動画。冒頭フック + 下部テロップのプロ仕様レイアウト + キャプション + 音楽提案 |

### リールとストーリーの使い分け

Instagramでの役割が違うため、見せ方を作り分けています。

- **リール** — 発見タブで新規リーチを取るための動画。**映像が主役**で、テキストは冒頭のフックと下部テロップ(POINTチップ + 見出し + 字幕)だけに絞ります。背景は Sora のAI動画やアップロード動画をそのままフルに見せ、暗幕(スクリム)も薄くしています
- **ストーリー** — 既存フォロワー向けの24時間限定コンテンツ。**テキストが主役**で、1文字ずつ現れるキネティックタイポグラフィ、シーン切替のワイプ、上部プログレスバーといったスライド演出を使います。静止画と動画の両方を書き出せます

## プロ品質のための機能

- **MP4書き出し (WebCodecs)**: リールは1フレームずつ正確に描画してH.264/MP4にエンコード。フレーム落ちがなく、そのままInstagramに投稿できます(非対応ブラウザでは自動的にWebMへフォールバック)
- **AI Bロール動画 (Sora)**: リール背景として、OpenAI Sora がブランドに合わせたCM風の実写映像を生成。2つの構成から選べます
  - **シーンごとにカット割り(推奨)**: フック→ポイント→CTAの各シーンが別々の映像に切り替わる、テレビCMと同じカット編集(4秒×シーン数、約$0.4×シーン数)
  - **1本の映像**: 8秒1本を全シーン共通の背景に(約$0.8)
  - 毎回ランダムなカメラワーク(ドリーイン/トラッキング/俯瞰など)とライティング(ゴールデンアワー/ハイキーなど)が付与され、**作り直すたびに違う映像**になります。`OPENAI_VIDEO_MODEL=sora-2-pro` でさらに高品質な映像も選択可(料金約3倍)
- **ブランドロゴ**: 透過PNGをアップロードすると全テンプレートの定位置に自動配置
- **ブランドキット保存**: ロゴ・HP URL・ブランド説明をブラウザに保存し、次回起動時に自動復元
- **モーションデザイン**: 1文字ずつ現れるキネティックタイポグラフィ、シーン切替のワイプトランジション、浮遊パーティクル、フィルム風ビネット、CTAボタンのパルスなど

## 採用アカウントモード

「アカウントの目的」を **👥 採用(公式採用アカウント)** に切り替えると、企業の公式採用アカウントの運用作法に沿った設計に変わります。

**投稿の型を12種類から選べます** — 社員インタビュー / 社員の1日 / 数字で見る会社 / 福利厚生・制度 / オフィス・職場紹介 / 選考フロー / 求職者からのQ&A / 職種・仕事内容 / 新入社員・内定者の声 / 社風・カルチャー / 代表・先輩メッセージ / 募集要項

型に応じてカルーセルの構成そのものが変わります。「社員の1日」なら1枚1時刻の6〜8枚構成、「選考フロー」なら1枚1ステップ、「数字で見る会社」なら1枚1数字といった具合です。

**採用アカウント向けの設計指針**(AIに組み込み済み)

- 主役は「人」。会社の実績や設備ではなく、そこで働く個人の顔・言葉・1日を描く
- 求職者が本当に知りたい6項目(仕事内容 / 1日の流れ / 一緒に働く人 / 給与・休日・残業の実態 / キャリア / 選考の進み方)に正面から答える
- 「アットホームな職場」「風通しがいい」「若手が活躍」といった、求職者に最も警戒される常套句を使わず、それを証明する事実と数字に置き換える
- 年齢・性別・国籍を限定する表現を書かない(職業安定法・男女雇用機会均等法への配慮)。「若手歓迎」「女性活躍中」も自動的に避けます
- ハッシュタグに勤務地の地名タグを必ず含める(求職者の検索行動に直結するため)
- 背景画像は商品写真ではなく「働く人と職場」を、日本のオフィス・現場として描写する

**追加の入力欄**(すべて任意・埋めるほど具体的になります): 対象 / 募集職種 / 勤務地 / 会社の数字 / 福利厚生・制度 / 社員の声・エピソード / 求める人物像 / 選考フロー / 応募導線

## 参考素材のアップロード(任意)

- **写真(最大3枚)**: AIが視覚分析してコピー・配色・背景に反映。1枚目はフィード/ストーリー/リールの背景としてそのまま使うことも、OpenAIの画像編集APIで「写真を参考にしたAI背景」に仕上げることもできます
- **動画(1本)**: リール動画の背景として実写映像を使用できます(テキストアニメーションを自動合成)。動画はサーバーに送信されず、ブラウザ内でのみ処理されます

## 仕組み

1. **サイト分析** — 入力された企業HPをサーバー側で取得し、タイトル・説明・本文テキストを抽出
2. **AI設計** — Claude (claude-opus-4-8) がブランド分析を行い、配色・フォント・テンプレート選定・コピーライティング・キャプション・ハッシュタグ戦略・背景画像プロンプトまでを構造化データとして設計
3. **AI背景生成(任意)** — OpenAI の画像生成API (**gpt-image-2**) でブランドに合わせた商業写真クオリティの背景を生成。Canvasの実サイズに合わせて 4:5 は 1088×1360、9:16 は 1088×1920 のネイティブ解像度で受け取るため、拡大による劣化がありません
4. **レンダリング** — ブラウザのCanvas APIで背景の上に日本語の文字組みを重ね、画像・動画としてエクスポート

日本語テキストはCanvasで描画するため、画像生成AIにありがちな**文字化け・崩れが起きません**。Anthropic APIキーのみでも動作し(テンプレート背景)、OpenAI APIキーを追加すると「✨ AI写真」背景が使えます。

# 2. 環境変数の設定

http://localhost:3000 を開き、フォームに入力して「コンテンツを生成する」を押してください。

## 使い方のコツ

- **企業HPのURL**: トップページのURLを入れると、AIが事業内容・トーンを自動分析します
- **企業イメージ**: ターゲット層・ブランドの雰囲気・強みを書くほど精度が上がります
- **文言**: キャンペーン情報や期限など、画像に必ず入れたい内容を書いてください
- 生成後もテンプレートを切り替えてデザインの候補を比較できます
- **「✨ AI写真」テンプレート**を選ぶと、ブランドに合わせた写真背景をその場で生成します(OpenAI APIキーが必要。1枚あたり数円〜数十円の従量課金)
- リール動画は「AI写真背景」に切り替えるとKen Burns効果(ゆっくりズーム)付きの写真背景になります
- リールは映像素材があるほど本領を発揮します。Sora のAI動画、またはご自身で撮影した動画のアップロードをおすすめします
- 文字を主役にしたスライド演出の動画がほしいときは、ストーリータブの「🎬 動くストーリー」を使ってください
- OpenAIの新しい画像モデルが出たら `.env` の `OPENAI_IMAGE_MODEL` を変えるだけで切り替えられます

# Indeed 求人診断 (`/indeed`)

Indeed から取れる **表示数 / クリック数 / 応募数** を登録すると、同じ業種・職種・雇用形態の求人と比較して
「表示 → クリック → 応募」のどこが詰まっているかを判定し、改善提案を優先度順に出します。

実績と施策の記録を貯めるほど、**比較基準そのものと、提案の並び順の両方が自分のデータに置き換わっていきます。**

## まず出るのは「考察」1 つ

求人を開くと、細かい数字より先にこれが出ます。

```
【一覧には出ているのに、選ばれていません】

クリック率が 1.0%(基準 2.8% の 36%)。60,000 回表示されて、クリックは 600 回だけです。

求職者が検索結果の一覧で見ているのは、タイトル・給与・勤務地・キャッチコピーの4つだけです。
詳細を開くかどうかはここで決まるので、この4つのどれかが並んでいる他社に負けている
ということになります。実際に確認できた範囲では、キャッチコピーに給与と休日・勤務時間の
記載がありません。詳細まで来た人の応募率は基準以上なので、中身は悪くありません。
入口の見せ方だけの問題です。

やること: 1) キャッチに給与と休日・勤務時間を入れる
          2) キャッチコピーを70文字まで使い切る
          3) タイトルに条件を1つ足す(未経験可・土日休みなど)

クリック率を基準並みまで戻せれば、月の応募は今の約 63.9 件から 176.3 件前後。
上位25%の水準まで持っていければ 264.5 件前後です(他の段階が今のままという前提の単純計算です)。
```

考察は 5 つのセクションで構成されます。

| セクション | 何を見るか |
|---|---|
| **現状** | 他社ベンチマークとの比較(横の比較)。集計期間の季節に合わせて基準を補正します |
| **推移** | 前期からどう変わったか(縦の比較)。季節要因を差し引いた実質の変化で判定します |
| **自社の他求人との比較** | 同職種の自社求人の中で何位か、上位の求人と何が違うか |
| **原因の見立て** | 上の3つを踏まえて、なぜそうなっているのか |
| **時期について** | 今が動く時期か閑散期か、次の月に何が来るか |
| **見込み** | 直した場合の応募数、プラン全体をやりきった場合、次に効いてくる段階 |

そのままお客様への報告に使える文章になっています(コピーボタンつき)。
数字の内訳やベンチマークの粒度は、その下に畳んであります。

### 推移の分析 — `lib/indeed/trend.ts`

同じ「クリック率 2.7%」でも、先月 3.4% から落ちてきたのか、2.1% から戻してきたのかで
打つべき手はまったく変わります。落ちているなら原因の特定が先で、戻してきているなら今やっていることを続けるのが正解です。

指標の組み合わせから原因を読み分けます。

- **表示増 × CTR減** → 露出が広がって関心の薄い層にも出ている。予算を増やした直後なら想定内
- **表示横ばい × CTR減** → 競合が増えたか、原稿変更が逆効果。露出では説明がつかない
- **CTR増 × 応募率減** → 一覧での見せ方が実際の条件より魅力的すぎて、開いた人がギャップで離れている
- **表示が大幅減** → 予算・掲載順位・有効期限の問題。原稿ではない

変化した期間に施策を記録していれば突き合わせて、「その施策の後に悪化しているので戻すか切り分けを」まで言います。
3 期間以上あれば、一貫した下降・上昇も検出します。

### 自社の他求人との比較 — `lib/indeed/peers.ts`

ベンチマークは「同セグメントの平均はこのくらい」までしか教えてくれません。
現場で本当に知りたいのは「うまくいっている求人は、この求人と何が違うのか」です。

同職種・同雇用形態の自社求人の中で順位を出し、成績が上の求人と属性を突き合わせて差分を出します。

```
自社で登録している同職種・同雇用形態の求人 4 件中 4 位です
(クリック率 3.2%、最も高いのは「【春日井市】リフト/土日休み」の 5.5%)。

・成績が上の 3 件は給与の中央値が 1,400円。この求人は 1,250円 で、11% 低い水準です
・成績が上の 2 件は給与を「〜円」の範囲で見せています。この求人は単一提示です
・成績が上の 2 件は職場写真を載せています。この求人は未掲載です
・成績が上の 2 件はキャッチコピーに給与を書いています。この求人は書いていません
```

比較するのは給与・給与の上限表記・スポンサー掲載・職場写真・キャッチコピーの内容と長さ・
仕事内容の構成・応募フォームの設問数です。「上位群の過半数がそうしていて、この求人はそうしていない」
ものだけを挙げるので、当てはまらない指摘は出ません。

### 季節変動の補正 — `lib/indeed/season.ts`

求人の成果は月で大きく上下します。これを無視すると 3 つが同時に壊れます。

1. **診断** — 8月の落ち込みを「原稿が悪い」と誤診する
2. **推移** — 7月→8月の自然な減少を「悪化した」と報告する
3. **効果測定** — 7月に打った施策を8月の数字で測って「効かなかった」と誤学習する

3 が特に厄介で、放置すると学習そのものが逆方向に進みます。そのため季節指数で補正しています。

```
8月はお盆をはさみ、年間で最も求職者が動かない月のひとつです。応募が落ちるのは
自然な変動で、原稿の問題とは限りません。この時期は例年 -9% 程度落ちるので、
以下の変化はその季節要因を差し引いた実質の値で見ています。

見かけ上は 表示数 -21% と動いていますが、季節要因を差し引くと 表示数 +3% で、
実質的には横ばいです。時期どおりの動きなので、この変化を理由に原稿を触る
必要はありません。
```

**「求人が多い時期」と「応募が多い時期」は別物**です。企業は 8〜10月に求人を出しますが
(10月入社・下期に向けて)、求職者は 8月のお盆には動きません。調べた記事の多くがこの 2 つを
混同していますが、このツールが扱うのは応募数なので**求職者側の動き**を採用しています。

**指標ごとに感応度を変えています。** 季節で変わるのは主に求職者の母数なので、影響が最も大きいのは
表示数(感応度 1.0)。クリック率は一覧に並んだ求人の中での相対的な選ばれ方なので母数が減っても
大きくは動かず(0.15)、応募率はその中間(0.4)としています。

業種・雇用形態ごとにカーブが変わります(調査結果と突き合わせて検算済み)。

| セグメント | ピーク | 底 | 12月 |
|---|---|---|---|
| 飲食 × アルバイト | **5月 (1.17)** | 8月 (0.80) | 0.80 |
| 物流 × 派遣 | 3月 (1.27) | 8月 (0.73) | 0.93 |
| 介護 × 正社員 | 1月 (1.21) | 5月 (0.83) | 0.83 |
| 販売 × 派遣 | 3月 (1.27) | 8月 (0.73) | **0.98** |

飲食だけ 5月がピークなのは、大学生の履修が確定してからバイトを探し始めるためです
(Indeed の調査で確認)。販売の 12月が落ちないのは、年末の短期バイト需要があるためです。

時期に応じた動き方の助言も出します。閑散期には「応募が少ないのは時期の問題なので、慌てて条件を
下げないでください。他社も掲載を控えるので出し続ければ埋もれにくい利点があります」、
繁忙期には「ここで取り切れないと年間計画に響きます」、そして必ず**次の月に何が来るか**を添えます。

> ⚠ 季節指数の初期値は、下記の記事ベースの定性情報から組み立てた推定値です。公開された月次指数ではありません。
> ベンチマークや施策効果と同じく、自社の実績が月をまたいで貯まるほど実測の指数に置き換わります
> (求人ごとに「その求人の全期間平均に対する各月の比」を取り、求人をまたいで平均するので、
> 求人の入れ替わりや規模の違いに影響されません)。

### 実行プラン

改善策は実施の重さで 3 つに分けて出します。着手の判断がしやすくなるためです。

- **今すぐできる** — 管理画面の設定変更だけで終わる
- **今週中に** — 原稿の書き換えが必要
- **クライアントに相談** — 条件そのものの見直しが必要

各グループの中は効果の大きい順です。あわせて「プランを一通りやりきった場合」の見込みも出します。
同じ段階の施策は効果が重なるので足し算せず、その段階で最も効くもの 1 つで見積もり、
段階をまたぐぶんだけ掛け算しています(各段階とも上位25%で頭打ちにします)。

最後に「次に効いてくる段階」を示します。CTR を直したら次は応募率が効いてくる、という順序が見えるためです。

考察は AI ではなく `lib/indeed/insight.ts` のロジックが書いています。同じ数字からは必ず同じ考察が出ます。
ファネル 3 段階の組み合わせから、求人が置かれている状態を 6 パターンに判定します。

| パターン | 意味 | 主な打ち手 |
|---|---|---|
| **見られていない** | 表示数が基準割れ | 予算・入札、タイトルの職種名と勤務地 |
| **選ばれていない** | 表示はあるが CTR が低い | 給与の見せ方、キャッチコピー、タイトル |
| **応募されていない** | クリックはあるが応募率が低い | 仕事内容の構成、応募フォーム、選考フロー |
| **条件で負けている** | CTR・応募率とも低い | 給与・休日など条件そのものの見直し |
| **詰まりなし** | 3 段階とも基準以上 | 予算を足して露出を伸ばす |
| **判定待ち** | 母数が足りない | もう 1 期間ぶん実績を貯める |

一覧画面には全求人をまとめた考察も出ます
(「5件のうち2件が『見られていない』— ここが最大の塊です」)。
同じ原因で詰まっている求人はまとめて直したほうが速いためです。

### 見込みの数字について

「上位25%まで行けます」とだけ言うのは過大な期待になるため、考察では
**基準並みまで戻した場合を本線**にし、上位25%は上振れたときの数字として添えています。
どちらも「他の段階が今のまま」という前提の単純計算であることも毎回明記します。

クリック率・応募率がまだ判定できる母数に達していない求人では、**応募増の試算そのものを出しません**。
ベンチマーク由来の率で応募数を計算しても、数字だけが独り歩きするためです。

## 何が「合理的」なのか

このツールの設計判断は 3 つです。

### 1. 数値の判断は AI にさせない

集計・ベンチマーク比較・ボトルネック特定・優先順位づけは、すべて `lib/indeed/` の決定論的な計算です。
AI が担当するのは、確定した診断結果を前提にした**言葉づくり**(キャッチコピー案・仕事内容案・お客様向け報告文)だけです。
そのため、同じデータからは毎回同じ診断が出ますし、AI が数字を作ることもありません。

### 2. 「率が一番悪いところ」ではなく「直すと応募が一番増えるところ」から並べる

CTR が半分でも表示数が 200 しかない求人より、CTR が 8 割でも表示数が 5 万ある求人のほうが、直したときのリターンは大きい。
そのため提案の並び順は次の式で決めています。

```
期待応募増 = min( 現在の月間応募数 × その施策の期待リフト率 , その段階を上位25%水準に戻したときの伸びしろ )
優先度     = 期待応募増 ÷ 実施の重さ × 段階の判定による重み
```

「段階の判定による重み」は、統計的に基準を下回っていると言い切れる段階(要改善)を、
ブレの範囲内の段階(標準)より優先するためのものです。

### 3. 母数が小さいときは「判定しない」と言う

表示 200 回・クリック 2 回で「CTR 1% だから要改善」と言うのはただのノイズです。
クリック率は表示 300 回以上、応募率はクリック 30 件以上を判定の最低ラインとし、
それ未満は **判定保留** として提案対象から外します。
判定にも Wilson 信頼区間を使い、「区間の上端が基準値を下回る = ブレではなく本当に低い」ときだけ要改善と判定します。

## どうやって学習するのか

学習は 2 系統あります。どちらも画面の「🧠 学習状況」タブで進み具合を数字で確認できます。

### ① 比較基準(ベンチマーク)の学習 — `lib/indeed/benchmark.ts`

「この業種のこの職種なら普通はこのくらい」という基準値を、登録済みの実績から作ります。

- **階層構造**: 業種 × 職種 × 雇用形態 → 業種 × 雇用形態 → 業種 → 全体 → 業種別の暫定値、と 4 段階で親をたどります。細かいセグメントのデータが少なくても、親のデータで補って推定できます
- **経験ベイズ収縮**: 各階層の推定値は「実測値」と「親の推定値」の加重平均で、重みはデータ量そのものです。**データが増えるほど自動的に実測寄りになります**。1 件目の登録から破綻せずに動き、蓄積が進むと自前の基準値に置き換わります
- **ハウスファクター**: 「暫定値がこの求人群に対して予測した数値」と「実際の数値」の比を取り、まだデータのない業種にも自分の事務所固有の上振れ・下振れを引き継ぎます
- **給与相場**: 登録済み求人から、同じ地域・同じ職種・同じ雇用形態の給与中央値を算出します。求人が増えるほど「相場より 21% 低い」という具体的な根拠つきで提案できるようになります

反映度は「累計表示数 ÷ (累計表示数 + 10,000)」で、累計 1 万表示でちょうど半分、10 万表示で 9 割が自社データに置き換わります。

### ② 施策効果の学習 — `lib/indeed/learn.ts`

ベンチマークが学ぶのは「何が普通か」。こちらが学ぶのは「**何をやると効くか**」です。

1. 求人の詳細画面で、実施した施策にチェックを入れて記録する
2. 施策日の前後 6 週間の実績を突き合わせ、CTR / 応募率 / 1日あたり表示数の相対リフトを測る
3. 施策ごとにリフトを集計し、初期値(カタログに書いた想定効果)から実測値へ徐々に置き換える
4. 提案の期待値と並び順に、その実測効果量を反映する

効果がなかった施策のマイナス値も学習に使われるため、**効かない施策は自動的に提案の上位から消えます。**

測定の扱いで気をつけている点:

- 同じ日に複数の施策を打つとどれが効いたか分離できないため、1/n の重みで按分します(画面上でも「1〜2 個ずつ打つと学習が速い」と案内しています)
- 統計的に有意でない観測も捨てずに使いますが、有意なものより重みを下げます(求人 1 件ごとの母数は小さく、有意なものだけでは学習が何年も進まないため)
- 極端な外れ値は丸めます(1 件の異常値で提案順が壊れないように)
- 施策日をまたぐ集計期間は、どちらの効果か分離できないため測定から除外します

## 業種ごとの提案

改善施策カタログ (`lib/indeed/playbook.ts`) には、表示数 7 件 / クリック率 9 件 / 応募率 12 件の施策が入っています。
各施策は「その求人で提案する根拠」を必ず返すため、提案は検証可能な指摘になります。

> ❌ 「CTR が低いのでタイトルを見直しましょう」
> ✅ 「タイトルに『小牧市』が入っていません。地名検索でヒットしにくい状態です」
> ✅ 「提示 1,100円 に対し、同セグメント 4 件の中央値は 1,400円。相場より 21% 低い水準です」
> ✅ 「キャッチコピーが全角 16 文字(上限 70 文字の 23%)。あと 54 文字ぶんの訴求枠が空いています」

業種は 15 種類(製造・軽作業 / 物流・運輸 / 介護・福祉 / 医療 / 飲食 / 販売・接客 / 事務 / 営業 / 建設・施工 / IT / 清掃・警備 / 保育・教育 / コールセンター / 美容・理容 / その他)で、
それぞれ「その業種の求職者が必ず気にすること」を持っています。応募率が低い求人では、その項目に原稿が答えているかを実際に照合して指摘します。

## 原稿チェックと法令対応

原稿(求人タイトル・キャッチコピー・仕事内容)を登録すると、機械的なチェックが走ります。判定基準は運用ルールに合わせています。

- キャッチコピー: 全角 70 文字以内 / 枠の使用率 / 給与・休日の記載 / 「20〜50代活躍中」/ 常套句の検出
- 仕事内容: ◆◆3ブロック構成 / 350 文字前後 / 1 行 24 文字以内 / ポイント 8 個以内 / 数字の有無
- 表現チェックは **法令** と **運用ルール** を分けて表示します
  - 法令: 年齢を限定する表現(「35歳まで」)、性別を限定・示唆する表現、断定的な誇大表現
  - 運用ルール: 「○○歓迎」→「○○活躍中」、「主婦」→「しゅふ / 主婦（夫）」

法令にふれうる表現は、**成果が良好な求人でも提案として必ず表示します**(成果とは別軸の問題のため)。

## Chrome で開く

このアプリは自分のパソコンで動かします(データも自分のパソコンの中だけに保存されます)。

**1. Node.js を入れる**(初回だけ)

<https://nodejs.org/ja> から LTS 版をダウンロードしてインストールします。
インストール済みかどうかは、ターミナル(Windows なら PowerShell)で `node -v` を実行して
`v20` 以上が表示されれば OK です。

**2. アプリを起動する**

```bash
git clone https://github.com/sho19910626/CLAUDE_CODE_GIT_BASH_PATH.git
cd CLAUDE_CODE_GIT_BASH_PATH
npm install     # 初回だけ(数分かかります)
npm run dev
```

**3. Chrome で開く**

<http://localhost:3000/indeed>

`Ctrl + C`(Mac は `⌘ + C`)で停止します。次回からは `npm run dev` だけで起動できます。

> **APIキーは不要です。** 診断・考察・改善提案・学習はすべてブラウザとサーバー内の計算だけで動きます。
> 「✨ 改善案を作る」(AIによる原稿・報告文の作成)を使うときだけ、`.env` に `ANTHROPIC_API_KEY` が必要です。

### うまく動かないとき

| 症状 | 対処 |
|---|---|
| `npm: command not found` | Node.js が入っていません。手順 1 に戻ってください |
| `Error: listen EADDRINUSE :::3000` | 3000番ポートが使用中です。`npm run dev -- -p 3001` で別のポートで起動してください |
| ページが真っ白 | ターミナルにエラーが出ていないか確認してください。`npm install` のやり直しで直ることが多いです |
| データが消えた | ブラウザの履歴・サイトデータを消すと一緒に消えます。定期的に「💾 書き出し」でバックアップを取ってください |

### データはどこにありますか

Chrome の localStorage(キー `indeed-analytics-v1`)に保存されます。
**同じパソコンの同じ Chrome でのみ見えます。** シークレットウィンドウでは保存されません。
別のパソコンや別のブラウザで使いたいときは、「💾 書き出し」で JSON を保存して
「📂 読み込み」で取り込んでください。

## 使い方

1. **📥 実績を取り込む** — Indeed の管理画面やスプレッドシートで表を選択してコピーし、そのまま貼り付けます
   - 必須列: 求人名 / 表示数 / クリック数 / 応募数(1 行目を見出し行に)
   - 任意列: 会社名 / 業種 / 職種 / 雇用形態 / 都道府県 / 時給 / 期間 / 費用
   - タブ区切り(コピペ)と CSV の両方、「1,234」「¥5,000」「12.3%」といった書式付きの数値にも対応します
   - CTR・応募率の列は読み込みますが、値は表示数・クリック数・応募数から計算し直します(食い違えば警告します)
   - 同じ求人・同じ期間のデータは上書きされるため、毎月同じ表を貼り直しても二重計上になりません
2. **📊 求人一覧・診断** — 求人をクリックすると、ファネル図・段階別の判定・改善提案が出ます
3. **求人を編集** — 原稿・給与・応募フォームの設問数などを登録すると、提案が具体的になります
4. **施策を記録** — 実施した提案にチェックを入れて記録します。**これがツールの精度を上げる唯一の入力です**
5. **✨ 改善案を作る** — 診断結果をもとに、キャッチコピー案・仕事内容のリライト案・お客様向け報告文を AI が作成します
6. **🧠 学習状況** — ベンチマークの反映度と、施策ごとの実測効果を確認できます

## 精度を上げるためにやること

1. **毎月、実績を登録する** — ベンチマークが自社データに置き換わり、前後比較による効果測定もできるようになります
2. **職種名の表記を揃える** — 「フォークリフト」と「フォークリフト作業」は別セグメント扱いです。揃えるほど細かい粒度で比較できます
3. **原稿を登録する** — 提案が「CTRが低い」から「キャッチが 38 文字しか使えていない」に変わります
4. **施策は 1〜2 個ずつ打って記録する** — 同時に 5 個変えると、どれが効いたか分離できません
5. **効果がなかった施策も記録する** — マイナスの実測値も学習に使われます
6. **定期的に「💾 書き出し」でバックアップを取る** — 蓄積が消えると精度も戻ってしまいます

## データの保存について

データはブラウザの `localStorage`(キー `indeed-analytics-v1`)に保存されます。サーバーには送信されません
(AI 提案を実行したときだけ、その求人 1 件ぶんの情報が Anthropic API に送られます)。

端末をまたいで使う場合や、バックアップを取る場合は **💾 書き出し / 📂 読み込み** の JSON を使ってください。
読み込みは既存データへの統合(マージ)なので、複数人ぶんのデータを 1 つにまとめることもできます。

複数人でリアルタイムに共有したくなった場合は、`lib/indeed/store.ts` の `readStore` / `writeStore` を
サーバー API に差し替えるだけで移行できます(画面側はこのファイル経由でしかデータに触れていません)。

## ベンチマークの初期値について

> ⚠️ `lib/indeed/seed.ts` の数値は **実データが 1 件もないときだけ使う暫定の初期値**です。
> 求人媒体の成果は同じ業種でもエリア・予算・時期で大きく振れるため、この値そのものを正解として扱ってはいけません。
> 実績を登録するほど自分のデータで置き換わっていき、初期値の影響は自動的に薄まります。
> 画面には常に「暫定値 / 実データ何件から算出」を表示しているので、判定の根拠がどちらなのかは毎回確認できます。
