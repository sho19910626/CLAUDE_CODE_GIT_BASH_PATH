# 商談ナビ — DFA Robotics 活動報告ジェネレーター

議事録を貼って生成ボタンを押すと、**現場の記入フォーマットのまま**、
そのまま Salesforce の商談メモに貼れる活動報告になります。
STEP1（商談準備）は、企業名とHPを入れるだけで、ネット・SNS・求人情報まで
調べたうえで準備シート・想定問答・トークスクリプトを作ります。

対応している 7 つの STEP:

| STEP | 名前 | 入力 | 出す物 |
|---|---|---|---|
| ① | 商談準備 | 企業名・HP・商談日時・参加者 | 準備シート＋想定問答＋トークスクリプト＋当日取るもの |
| ② | 商談報告 | 議事録 | フォーマット＋BANTC の抜け漏れ＋ネクストアクション |
| ③ | デモ・検証設定報告 | 議事録 | 同上（現調結果・成功条件の合意まで） |
| ④ | POC設置報告 | 議事録 | 同上（運用体制・中間報告日まで） |
| ⑤ | POC評価報告 | 議事録 | 同上（検証結果の判定・テストクロージング） |
| ⑥ | 稟議支援・上申状況報告 | 議事録 | 同上（上申タイミング・保守/補助金の確定） |
| ⑦ | 内諾報告 | 議事録 | 同上（金額・購入方法・納期の合意） |

## いちばん大事な作り

### 議事録に無いことは、書きません

埋まらなかった欄は **「未確認」** とだけ出します。そのうえで画面の下に
**「この報告で埋まっていない項目」** を並べ、次回そのまま口に出せる質問文を添えます。

もっともらしく補完すると、それが社内で事実として一人歩きし、
稟議や納品の段で食い違います。**埋まっていない欄がある報告のほうが、
埋まっているように見える報告よりずっと価値がある** という前提で作っています。

### フォーマットの行は、増えも減りもしません

見出しと項目名は [`lib/steps.ts`](lib/steps.ts) が唯一の正で、本文の組み立ては
[`lib/format.ts`](lib/format.ts) がやります。AI に本文をそのまま書かせていないので、
何十件並んでも行の順番と文言が毎回同じです。

（フォーマットを変えるときは `lib/steps.ts` のラベルを直します。
AI に渡す項目説明も、画面のヒントも、そこを見ています。）

### 前の STEP を引き継ぎます

同じ案件の STEP2 以降は、前の STEP で確定した事実を読み込んでから生成します。
そのため「当初の仮説とのギャップ」「STEP3 で合意した成功条件の達成可否」まで判定できます。
引き継ぐのは判定と矛盾の指摘に使うためで、**前回の文章を今回のファクト欄に
書き写すことはしません**（今回の議事録に出た話だけを書きます）。

### ネクストアクションは「誰が・いつまでに・何を」

期限は実日付で出します。あわせて、顧客に送るフォローメールの文面案も作ります。

## セットアップ

```bash
cd sales-console
npm install
cp .env.example .env    # 値を入れる
npm run dev             # http://localhost:3003
```

`.env` に入れるもの（3つ）:

| 変数 | 何に使うか |
|---|---|
| `ANTHROPIC_API_KEY` | 報告書の生成と、STEP1 の企業リサーチ |
| `APP_PASSWORD` | ログインの署名の鍵。最初の管理者を作るときの合言葉も兼ねる |
| `DATABASE_URL` | アカウントと、案件・議事録・報告本文の置き場（Neon） |

`DATABASE_URL` は**既存の Neon をそのまま使えます**。このツールのテーブルは
`sales_` で始まるので、他のツール（`insta_` / `avatar_`）とは混ざりません。
アカウントのテーブルも別なので、**営業メンバーのアカウントはこのツールで新規発行**します
（採用系ツールの利用者が、営業情報を見られるようにはなりません）。

### 最初の1回

1. `APP_PASSWORD` と `DATABASE_URL` を入れて起動する
2. ログイン画面が「最初の管理者を作る」に変わっているので、
   お名前・パスワード（12文字以上）・合言葉（＝`APP_PASSWORD` の値）を入れる
3. 右上の「アカウント管理」から、営業メンバーのアカウントを 1 人 1 つ発行する

### 公開する（Vercel）

Vercel で `sales-console` をルートディレクトリに指定した新規プロジェクトを作り、
Environment Variables に上の3つを入れてから Deploy します。
入れ忘れると本番では誰もログインできません（素通しにはなりません）。

## 使い方

### STEP1（商談準備）

1. 左の「＋ 新しい商談」を選び、商談名を入れる
2. 企業名・HP・業界・商談日時・参加者を入れる
3. 生成すると、ネット・SNS・求人情報・口コミまで調べたうえで
   準備シート（コピペ用）と、別紙（想定問答・トークスクリプト・当日取るもの）が出ます

リサーチには 1〜3 分かかります。拾った事実には出典が付きます。

### STEP2〜7（商談後）

1. 左で案件を選ぶ（前の STEP が引き継がれます）
2. STEP のタブを選び、日付・相手・当初のゴールを入れる
3. 議事録を貼って生成

AI 議事録ツールの要約でも、手書きメモでもそのまま貼れます。

### コピー

「提出する本文」タブの右上「コピー」で全文コピーできます。
商談名は入力した値に置き換わりますが、`{!Opportunity.Name}` のまま残したいときは
チェックボックスで切り替えられます。

## お手本を登録する（管理者）

`/admin` の下半分「お手本（生成の基準）」に、
**上長のOKが出た実際の報告**を STEP ごとに貼れます。貼ると、文体と粒度がそこに寄ります。
（中身は真似させません。書き方だけを真似させます。顧客名は仮名にしてください）

- **書き方の決めごと**: 全 STEP 共通のルール（金額は税抜、他社は「競合A社」と書く など）
- **差し戻される報告の例**: これを書くと戻される、という NG 例
- **STEP ごとのお手本**: 実際の報告をフォーマットごと

ここに貼ったものは共有データベースに入り、全員の生成に効きます。

---

## 顧客情報の扱い

- 案件・議事録・報告本文は**共有データベースにだけ**置きます。
  ブラウザ（localStorage）にも、サーバーのディスクにも残しません
- 本番（`NODE_ENV=production`）で `DATABASE_URL` が無いと起動しません
- 1 人 1 アカウント。退職・異動はアカウントを停止すれば、開いている画面もすぐ見られなくなります
- ログイン・報告の生成・アカウント操作は記録に残り、`/admin` の「操作の記録」で管理者が確認できます
- 全員をその場でログアウトさせたいときは `APP_PASSWORD` を変えます

## 中身の地図

| ファイル | 役割 |
|---|---|
| `lib/steps.ts` | 7つの STEP の定義。**フォーマットの文言はここが唯一の正** |
| `lib/format.ts` | 構造化データ → 貼り付ける本文の組み立て |
| `lib/schema.ts` | AI の構造化出力に渡す JSON Schema |
| `lib/prompt.ts` | AI への指示。禁止事項（補完しない）を先頭に置いている |
| `lib/knowledge.ts` | 自社・機種・業界・補助金の知識（**公開情報だけ**。価格は入れない） |
| `lib/playbook.ts` | 管理者が登録したお手本 |
| `lib/cases.ts` | 案件と報告の保管、前 STEP の引き継ぎ要約 |
| `app/api/generate/route.ts` | 生成の本体（STEP1 はリサーチ→整形の2段階） |
| `components/SalesConsole.tsx` | メイン画面 |
| `lib/auth*.ts` / `middleware.ts` | ログイン（他ツールと同じひな形。Cookie 名は `sales_session`） |

### 機種や制度が変わったら

`lib/knowledge.ts` を直します。価格・リース料・実績数値は**書かない**決まりです
（社外秘のため。必要になったら `/admin` の「書き方の決めごと」に入れてください）。
