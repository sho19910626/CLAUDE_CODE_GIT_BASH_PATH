# 営業・売上管理（sales-crm）

営業の進捗と売上を 1 か所で管理するツールです。取引先・商談・活動の記録・やること・売上・目標を扱います。

`insta-studio/` や `avatar-studio/` と同じく、**コードを共有しない独立アプリ**です。ポートは 3003、
データベースのテーブル接頭辞は `crm_`、ログインの Cookie 名は `sales_session` なので、
他のツールと同時に動かしても、同じ Neon データベースを使い回してもぶつかりません。

```
npm install
cp .env.example .env    # APP_PASSWORD と DATABASE_URL を書く
npm run dev             # http://localhost:3003
```

## 画面

| 画面 | パス | 何をするところか |
|---|---|---|
| **ダッシュボード** | `/` | 今月の売上と目標達成率、MRR、パイプライン、活動量と転換率 |
| **商談** | `/deals` | ステージ別のボード。カードを動かすとステージが変わる |
| **商談の詳細** | `/deals/[id]` | 金額の内訳、売上予定、活動の記録、やること |
| **取引先** | `/companies` | リードから取引中まで。窓口の担当者もここ |
| **売上** | `/revenues` | 月ごとの実績・見込み・目標。成果報酬の実績を入れるのもここ |
| **やること** | `/tasks` | 期限超過 / 今日 / これから |
| **取り込み** | `/import` | CSV から取引先をまとめて登録 |
| **設定** | `/settings` | ステージ・商材・売上目標（管理者だけ） |
| **アカウント管理** | `/admin` | アカウントの発行・停止と操作の記録（管理者だけ） |
| **導入先の会社** | `/orgs` | 他社へ入れるときの会社の発行（運営元の管理者だけ） |

## いちばん大事な考え方 — 4 つの売上を混ぜない

このツールは 4 種類の売上を扱いますが、**同じ足し算をしません**。混ぜると数字が実態からずれるためです。

| 形態 | いつ立つか | 契約金額の数え方 | MRR に入るか |
|---|---|---|---|
| **単発** | 受注した月に一度だけ | 単価 × 数量 | 入らない |
| **月額継続** | 契約が生きている月にずっと | 月額 × 契約月数 | **入る** |
| **成果報酬** | 毎月。金額は実績しだい | 単価 × 見込み件数 × 月数 | 入らない |
| **広告費の立替** | 毎月。**売上は手数料だけ** | 手数料 × 月数 | 入らない |

**預かった広告費は、どこにも売上として足しません。** 別の欄（`passthrough_amount`）で持ち、
ダッシュボードでも「このほかに、預かった広告費が◯円あります（売上には含みません）」と分けて出します。
ここを混ぜると、月商 30 万円の会社が 330 万円に見えてしまいます。

契約月数を**空**にすると「解約するまで継続」になります。この場合、売上の予定は
**常に 12 か月先まで自動で補充**されます（売上画面やダッシュボードを開いたときに補充が走ります）。
1 年後に「来月の見込みが 0 件」にならないようにするためです。

### 受注したときに起きること

商談を**種類が「受注」のステージ**に動かした瞬間に、明細から売上の予定が作られます。

- 単発 → 受注月に 1 件、**確定**として
- 月額継続 / 成果報酬 / 立替 → 契約月数ぶん、**見込み**として

見込みは、実績が出てから売上画面で金額を直し、「確定にする」を押します。月まとめでの確定もできます。

契約内容を後から変えた場合、作り直されるのは **今月から先だけ**です。過去の月に記録した実績は動きません。

### 解約

商談の詳細で、月額の明細の「解約する」から解約月を入れます。**解約月そのものは課金し、その翌月から**
MRR から外れます。すでに確定した売上は消えません。

## セットアップ

### 1. データベース（必須・ローカル開発でも）

顧客企業名・商談・売上を扱うため、保存先は共有データベースだけにしてあります。
**ファイル保存の代わりは用意していません**（用意すると、動かしているパソコンのディスクに顧客情報が残るため）。

[Neon](https://neon.tech) の無料枠で十分です。作った接続文字列を `.env` の `DATABASE_URL` に入れてください。

```
DATABASE_URL=postgresql://user:pass@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
```

テーブルは最初に開いたときに自動で作られます。

### 2. 入口のパスワード（必須）

`APP_PASSWORD` は、セッション Cookie の署名の鍵と、最初のセットアップの合言葉を兼ねます。

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

で作った値を `.env` に入れてください。**この値を変えると、その瞬間に全員のログインが切れます**
（全員をその場でログアウトさせたいときの手段です）。

### 3. 最初のログイン

`http://localhost:3003` を開くと「最初のセットアップ」が出ます。会社名・お名前・パスワード・
合言葉（`APP_PASSWORD` の値）を入れると、会社と最初の管理者ができ、ステージ 8 種と商材 4 種が入ります。

以降のアカウントは、管理者が `/admin` から発行します。**共有アカウントは作らないでください**
（誰が何をしたか辿れなくなります）。

### Windows でダブルクリック起動する

`.env` を用意したら、`sales-crm` フォルダの **`start-sales.bat`** をダブルクリックするだけで
起動し、ブラウザが自動で開きます（初回は依存関係の取得に数分かかります）。
デスクトップにショートカットを置いておくと楽です。

`.env` の書き忘れやポートの重複は、起動前に理由つきで止まります。

> **PowerShell を使うときの注意**
> Windows PowerShell では `&&` が使えません。`cd sales-crm && npm install` はエラーになり、
> **フォルダも移動しません**。行を分けるか `;` を使ってください。
>
> ```powershell
> cd sales-crm
> npm install
> copy .env.example .env
> npm run dev
> ```

### 4. インターネットに公開する

Vercel でこの `sales-crm/` フォルダをルートに指定してデプロイし、Environment Variables に
`APP_PASSWORD` と `DATABASE_URL` を入れて Redeploy します。入れ忘れると誰もログインできません
（素通しにはなりません）。

## 権限

| | 一般 | 管理者 |
|---|---|---|
| 取引先・商談・活動・やること・売上の閲覧と入力 | ○ | ○ |
| CSV の取り込み | ○ | ○ |
| ステージ・商材・目標の変更 | — | ○ |
| 取引先・商談・売上の**削除** | — | ○ |
| アカウントの発行・停止・権限変更 | — | ○ |
| 操作の記録の閲覧 | — | ○ |

画面でボタンを隠すだけでなく、**サーバー側でも毎回確かめています**。API を直接叩いても素通りしません。

ログイン、受注・失注、取引先の取り込み・削除、売上の確定・削除、アカウントの発行・停止は
`/admin` の「操作の記録」に残ります。

## 他社に入れる（マルチテナント）

最初に作られた会社が「運営元」になります。運営元の管理者は `/orgs` から**会社を発行**できます。

- 会社ごとに、取引先・商談・売上・ステージ・商材・操作の記録がすべて分かれます
- すべてのテーブルが `org_id` を持ち、データを取り出す関数は必ず `org_id` を `where` に入れます
- 会社を「停止」すると、その会社の人は誰もログインできなくなり、開いている画面もすぐ見られなくなります

お名前は会社ごとに一意です。同じお名前が複数の会社にあるときだけ、ログイン画面で**会社コード**を聞かれます
（パスワードが合った候補が 2 つ以上あったときだけ聞くので、「その名前が存在するか」は分かりません）。

## 中身の地図

```
lib/money.ts       4形態の金額計算・MRR・解約の判定 … 数字の正しさはここに集約
lib/crm.ts         取引先・商談・活動・やること・売上・目標の読み書き（全部 org_id つき）
lib/dashboard.ts   ダッシュボードの集計
lib/db.ts          接続とテーブル定義
lib/store.ts       会社・アカウント・操作の記録
lib/seed.ts        会社を作った直後に入れるステージと商材
lib/auth.ts        セッションの署名と検証
lib/auth-edge.ts   middleware 用の検証（署名 + アカウントと会社が有効か）
middleware.ts      全ページ・全APIをログイン必須にする
```

金額の計算は `lib/money.ts` だけで行います。画面やAPIでその場で足し算をしないのは、
同じ数字が場所ごとに違って見えるのを防ぐためです。

## 他のツールと違うところ

`APP_PASSWORD` 未設定のときに**ローカル開発でも素通しにしません**。
このツールは共有データベースが無いと何も表示できないため、素通しにすると
画面は開くのに中身がすべて「ログインが必要です」になり、原因が分からなくなるからです。
未設定のときはログイン画面へ送り、そこで理由を出します。

## まだ入れていないもの

必要になったら足せるように、あえて外してあります。

- **請求書の発行と入金の消し込み** — 今は売上の計上まで。請求は会計ソフト側で行う前提
- **データの書き出し（CSV / Excel）** — 手元にファイルが残る操作なので、必要になったら
  `/api/admin/export` に集約し、管理者だけ・記録つきで実装します（CLAUDE.md のルール 3）
- **Google カレンダー / メールの連携** — やることはツール内で完結させています
- **チーム階層の権限** — 今は「管理者」と「一般」の 2 つ。全員が全商談を見られます
