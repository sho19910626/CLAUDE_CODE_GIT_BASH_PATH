# note 収益化スタジオ

note で有料記事を売るまでを、**競合リサーチ → ジャンル選定 → アカウント設計 → 運用計画 → 記事作成 → 実績と次の一手**の
6 工程でひと続きに進めるツールです。ポート 3003 で動く独立アプリで、他のツールとコードを共有しません。

目標は「記事がたくさんできること」ではなく、**手取りで月いくら残るか**です。
目標は手取り 10 万 / 15 万 / 30 万 / 50 万円から選べ、額に応じて取るべき手段が切り替わります。
そのため実績を入れる工程を最後に置き、数字を見て次の一手を決めるところまでを 1 つのツールに入れています。

---

## 何ができるか

| 工程 | やること | 出てくるもの |
|---|---|---|
| ① 持ち札 | あなたの実績・エピソード・使える時間・目標（手取り）を入れる | 必要な売上と手数料の内訳 |
| ② 競合リサーチ | note の公開データを実際に取ってきて集計し、市場を読む | 価格帯・売れている型・空白・勝てない領域 |
| ③ ジャンル選定 | 市場 × 独自性 × 続けられるか × 単価 で採点 | 候補3〜5個と推奨1つ、目標までの算数 |
| ④ アカウント設計 | プロフィール・URL・タグ・マガジン・メンバーシップ | note にそのまま貼れるプロフィール文 |
| ⑤ 運用計画 | 手取り目標から逆算した 90 日の計画 | 収益の内訳・3つの期・記事カレンダー・週の回し方 |
| ⑥ 記事 | 記事を書く | 貼り付け用の全文（有料ラインの位置つき） |
| ⑦ 実績と次の一手 | 数字を入れる | 詰まっている段階の特定と、次にやること |

### 投稿は自動化していません

note には公開 API がなく、投稿の自動化はブラウザの自動操作になります。
規約上のリスクがあり、Vercel でも動かず、常時起動のマシンが別に必要になります。
このツールは**貼り付ければ済む状態まで**を自動化し、投稿ボタンだけ人が押す設計にしています。

## 設計で決めていること

### 数字を作らせない

AI に生データを丸投げすると、印象で語って数字を作ります。
集計は `lib/research.ts` で先に確定させ、AI には**集計済みの数字と実際のタイトル**だけを渡します。
分析の根拠には、実際に取得したタイトルを引用させています。

データが薄いときは、AI に「このデータの限界」を書かせて画面に出します（省略できないようにしてあります）。

### 目標は「手取り」で置く

note の売上はそのまま手元に入りません。決済手数料 → プラットフォーム利用料 → 振込手数料と引かれ、
**残るのは売上のおよそ 8 割**です。売上で目標を置くと、計画どおりに売れても手元の額が目標に届きません。

このツールは目標を必ず**手取り**で持ち、必要な売上を逆算します（`lib/revenue.ts`）。

| 目標（手取り） | 必要な売上 | 届くための形 |
|---|---|---|
| 月 10 万円 | 約 12.1 万円 | 単品の有料記事の積み上げで届く |
| 月 15 万円 | 約 18.2 万円 | メンバーシップで固定収入の土台を作り、単品を上に乗せる |
| 月 30 万円 | 約 36.3 万円 | 高単価商品か会員数が要る。note の外からの流入が前提 |
| 月 50 万円 | 約 60.4 万円 | note は入口。本業や講座など単価の高いものに繋ぐ形 |

**目標の額で、AI に渡す設計の指針が切り替わります。** 月 50 万円のときに
「有料記事を大量に書けば届く」という計画を書かせないためです。
使える時間で届かない目標なら、届かないと明記させます。

実績も手取りで見ます。振込の実額を入れればそれを使い、売上しか入れていなければ手数料を引いた概算で計算します。

手数料率は変わりうるので概算として扱い、画面にもその断りを出しています。
率が変わったら `lib/revenue.ts` の `FEES` を直せば全体に反映されます。

### 算数をサーバー側でも検算する

計画の「単価 × 本数 = 小計」「小計の合計 ≧ **必要な売上**」「週の作業時間 ≦ 使える時間」は、
AI の出力を信じずサーバー側で計算し直します。合わなければ画面に警告が出ます
（`app/api/steps/plan/route.ts`）。

必要な売上もサーバー側で確定させます。AI が手取りの額をそのまま売上として組んでしまうと、
計画どおり売れても手数料のぶん目標に届かないためです。

### 有料記事の形を強制する

- 無料部分が全体の 35% を切ったら警告（買う判断ができず売れないため）
- 有料部分が 1,500 文字未満なら警告
- AI が埋められなかった一次情報は `fillIns` として別枠に出し、本文には【 】で残す

### 顧客情報を端末に置かない

案件のデータ（リサーチ結果・戦略・記事・売上）はすべて共有データベースに置きます。
`localStorage` は使いません。書き出しは管理者だけができ、誰がいつ何件書き出したかが記録に残ります。

## 使いはじめる（かんたんな方法）

`note-studio` フォルダの **`setup.bat` をダブルクリック**してください。

1. Anthropic の API キーを聞かれる → 貼る
2. Neon の接続文字列を聞かれる → 貼る
3. あとは自動（`.env` の作成 → `npm install` → 起動 → ブラウザが開く）

入口のパスワードは自動で作られ、画面に表示されます（メモしてください）。
形が違うものを貼ると弾いて聞き直すので、間違った値のまま進むことはありません。

必要な 2 つの取り方は「手順 1／7」に書いてあります。

## 使いはじめる（手作業でやる場合）

初めて動かすまでの手順です。**上から順に、1 つずつ進めてください。**
各手順の最後に「こうなれば成功」を書いてあるので、そこを確認してから次に進みます。

所要時間は 15〜20 分（API キーとデータベースの取得を含む）。

### 手順 1／7　必要なものを 3 つ用意する

先に集めておくと、途中で止まりません。**まだ設定はしません。集めるだけです。**

**① Anthropic の API キー**

1. https://platform.claude.com/ を開く
2. ログイン（アカウントが無ければ作る）
3. 左メニューの「API Keys」→「Create Key」
4. 出てきた `sk-ant-` で始まる文字列をコピーして、メモ帳などに貼っておく

> ⚠ このキーは**表示されるのは 1 回だけ**です。閉じる前に必ずコピーしてください。
> 閉じてしまったら、作り直せば大丈夫です（古いほうは削除してください）。

**② データベース（Neon）の接続文字列**

1. https://neon.com/ を開く
2. ログイン（無料プランで足ります）
3. プロジェクトを作る（名前は何でもよい）
4. 「Connection string」に出ている `postgresql://` で始まる文字列をコピーしてメモ

**③ 入口のパスワードを自分で決める**

自分で好きな文字列を決めるだけです。どこかから取得するものではありません。

- 20 文字以上の、他で使っていない文字列にする
- 例：`note-studio-2026-kagi-8fj2` のように、意味のない文字を混ぜる

> このパスワードは、みんなが毎回入力するものではありません。
> **最初の管理者を作るときに 1 回だけ使う合言葉**であり、
> 同時にログイン状態を守る鍵でもあります。

**✅ こうなれば成功**：メモ帳に 3 つの文字列が並んでいる。

cd note-studio

### 手順 3／7　`.env` を作る

**`.env` は GitHub にはありません。あなたの手元で作るファイルです。**

API キーとパスワードが入るファイルなので、`.gitignore` で除外してあります。
git に入れてしまうと、リポジトリを見られる人全員に鍵が渡ってしまうためです。
GitHub にあるのは、中身が空の見本（`.env.example`）だけです。
だから GitHub 上で `note-studio/.env` を開こうとしても 404 になります。**それが正常です。**

見本をコピーして作ります。

```
cp .env.example .env
```

Windows のコマンドプロンプトなら：

```
copy .env.example .env
```

**✅ こうなれば成功**：`ls -a`（Windows は `dir /a`）で `.env` が一覧に出てくる。

---

### 手順 4／7　`.env` に値を書く

作った `.env` をテキストエディタで開きます。

```
notepad .env        # Windows
open -e .env        # Mac
code .env           # VS Code を使っている場合（OS共通）
```

`=` の**右側に、手順 1 でメモした値を貼り付けます**。書き換えるのは次の 3 行だけです。

| 行 | 何を貼るか |
|---|---|
| `ANTHROPIC_API_KEY=` | ① の `sk-ant-` で始まる文字列 |
| `APP_PASSWORD=` | ③ で自分が決めたパスワード |
| `DATABASE_URL=` | ② の `postgresql://` で始まる文字列 |

書けたら、こうなります（値は例です）。

```
ANTHROPIC_API_KEY=sk-ant-api03-xxxxxxxxxxxxxxxx
APP_PASSWORD=note-studio-2026-kagi-8fj2
DATABASE_URL=postgresql://user:pass@ep-xxx.neon.tech/neondb?sslmode=require
```

**よくある失敗**

| やりがちなこと | 正しくは |
|---|---|
| `ANTHROPIC_API_KEY = sk-ant-...` | `=` の前後に**空白を入れない** |
| `ANTHROPIC_API_KEY="sk-ant-..."` | **引用符で囲まない** |
| `# ANTHROPIC_API_KEY=sk-ant-...` | 行頭の `#` を**消す**（`#` があるとその行は無視されます） |
| 行末に空白が残っている | 値のうしろで改行する |

上書き保存して、エディタを閉じます。

**✅ こうなれば成功**：3 行とも `=` の右側が空でなくなっている。

### 手順 7／7　最初の管理者を作る

初回だけ、ログイン画面が「最初の管理者を作る」に変わっています。3 つ入力します。

1. **お名前** — あなたの名前（ログインにも表示にも使います）

### うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| GitHub で `note-studio/.env` が 404 | **正常です。** `.env` は git に入れていません。手順 3 で手元に作ります |
| 起動時に「DATABASE_URL が設定されていません」 | 手順 4 で `DATABASE_URL` が空か、行頭に `#` が残っています |
| 「DATABASE_URL のアドレスが間違っている可能性があります」 | 接続文字列の貼り間違いです。Neon の画面からコピーし直してください |
| 「ユーザー名かパスワードが違います」（データベース） | Neon 側でパスワードを再発行したのに、`.env` が古いままです |
| 「暗号化接続に失敗しました」 | `DATABASE_URL` の末尾の `?sslmode=require` が消えています |
| ログイン画面で「APP_PASSWORD が設定されていません」 | 手順 4 で `APP_PASSWORD` が空です。書いたあと**起動し直して**ください |
| 「初期設定の合言葉が違います」 | 入力した値と `.env` の `APP_PASSWORD` が一致していません。空白や引用符が混ざっていないか確認 |
| 「APIキーが無効です」 | `ANTHROPIC_API_KEY` の値が違うか、キーが削除されています。作り直してください |
| `.env` を直したのに変わらない | **`.env` は起動時にしか読まれません。** `Ctrl` + `C` で止めて `npm run dev` し直してください |
| ポート 3003 が使用中 | 別のアプリが使っています。`package.json` の `-p 3003` を別の番号に変えてください |

### インターネットに公開する（Vercel）

手元で動いたあと、みんなで使えるようにする手順です。

1. Vercel でこのリポジトリをインポートし、**Root Directory に `note-studio` を指定**する
2. Settings → Environment Variables を開く
3. 手順 1 で集めた 3 つを、**1 つずつ追加**する
   （`ANTHROPIC_API_KEY` / `APP_PASSWORD` / `DATABASE_URL`）
4. Deployments → 最新のものの「Redeploy」を押す

> `.env` は git に入っていないので、**Vercel には自動でアップロードされません。**
> 上の 3 番を必ずやってください。
>
> 入れ忘れると、本番で誰もログインできなくなります（誰でも入れる状態にはなりません。
> 開いてしまうより、止まるほうが安全だからです）。

**✅ こうなれば成功**：Vercel が出した URL を開くとログイン画面が出て、
手順 7 で作ったアカウントで入れる。

## note からのデータ取得について

note の公開ページが使っている JSON エンドポイントを読んでいます。**公開 API ではありません。**

- ログイン不要で、誰でも見られる情報しか取りません（記事タイトル・価格・スキ数・投稿日など）
- 1 回ごとに間隔を空け（既定 700ms）、1 リサーチあたりの回数にも上限（既定 40 回）があります
- note 側の都合で形が変わりうるため、複数のエンドポイントを順に試し、
  応答の形を決め打ちせずに「記事らしいオブジェクト」を探して拾う実装にしています

**取得できなくなったときは、「② 競合リサーチ」の「note との接続を確認」を押してください。**
いま実際に何が返っているか（ステータス・件数・生のデータ）が見えます。
403 や 404 が並ぶ場合は note 側の仕様が変わった可能性が高く、
`lib/note-api.ts` の `searchNotes()` にあるエンドポイント候補を足せば直せます。

## ファイルの地図

```
lib/note-api.ts    note の公開データを読む（エンドポイント候補・正規化・レート制限）
lib/research.ts    取ってきた記事から数字を出す（価格分布・スキ・投稿間隔・頻出語）
lib/prompts.ts     AI への指示。ツールの品質はほぼここで決まる
lib/schemas.ts     AI に返させる JSON の形。lib/types.ts と 1 対 1
lib/claude.ts      AI 呼び出しの共通部分
lib/revenue.ts     手数料の計算と、目標の段階ごとの設計指針
lib/store.ts       案件の保管（共有データベース）
lib/article.ts     記事を note に貼れる形にする

app/api/steps/*    6 工程それぞれの生成 API
app/api/note/diagnose  note との接続確認
app/api/admin/export   書き出し（管理者だけ・記録に残る）

components/Workspace.tsx  案件の作業場（タブ）
components/steps/*        各工程の画面
```

ログイン一式（`lib/users.ts` `lib/auth.ts` `lib/auth-edge.ts` `lib/rate-limit.ts` `middleware.ts` ほか）は
`insta-studio/` と同じものです。Cookie 名は `note_session`、テーブルの接頭辞は `note_` です。
