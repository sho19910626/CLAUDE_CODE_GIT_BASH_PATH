# note 収益化スタジオ

note で有料記事を売るまでを、**競合リサーチ → ジャンル選定 → アカウント設計 → 運用計画 → 記事作成 → 実績と次の一手**の
6 工程でひと続きに進めるツールです。ポート 3003 で動く独立アプリで、他のツールとコードを共有しません。

目標は「記事がたくさんできること」ではなく、**手取りで月いくら残るか**です。
目標は手取り 10 万 / 15 万 / 30 万 / 50 万円から選べ、額に応じて取るべき手段が切り替わります。
そのため実績を入れる工程を最後に置き、数字を見て次の一手を決めるところまでを 1 つのツールに入れています。

---

## 何ができるか

| 工程 | やること | 出てくるもの |
|---|---|---|
| ① 持ち札 | あなたの実績・エピソード・使える時間・目標（手取り）を入れる | 必要な売上と手数料の内訳 |
| ② 競合リサーチ | note の公開データを実際に取ってきて集計し、市場を読む | 価格帯・売れている型・空白・勝てない領域 |
| ③ ジャンル選定 | 市場 × 独自性 × 続けられるか × 単価 で採点 | 候補3〜5個と推奨1つ、目標までの算数 |
| ④ アカウント設計 | プロフィール・URL・タグ・マガジン・メンバーシップ | note にそのまま貼れるプロフィール文 |
| ⑤ 運用計画 | 手取り目標から逆算した 90 日の計画 | 収益の内訳・3つの期・記事カレンダー・週の回し方 |
| ⑥ 記事 | 記事を書く | 貼り付け用の全文（有料ラインの位置つき） |
| ⑦ 実績と次の一手 | 数字を入れる | 詰まっている段階の特定と、次にやること |

### 投稿は自動化していません

note には公開 API がなく、投稿の自動化はブラウザの自動操作になります。
規約上のリスクがあり、Vercel でも動かず、常時起動のマシンが別に必要になります。
このツールは**貼り付ければ済む状態まで**を自動化し、投稿ボタンだけ人が押す設計にしています。

---

## 設計で決めていること

### 数字を作らせない

AI に生データを丸投げすると、印象で語って数字を作ります。
集計は `lib/research.ts` で先に確定させ、AI には**集計済みの数字と実際のタイトル**だけを渡します。
分析の根拠には、実際に取得したタイトルを引用させています。

データが薄いときは、AI に「このデータの限界」を書かせて画面に出します（省略できないようにしてあります）。

### 目標は「手取り」で置く

note の売上はそのまま手元に入りません。決済手数料 → プラットフォーム利用料 → 振込手数料と引かれ、
**残るのは売上のおよそ 8 割**です。売上で目標を置くと、計画どおりに売れても手元の額が目標に届きません。

このツールは目標を必ず**手取り**で持ち、必要な売上を逆算します（`lib/revenue.ts`）。

| 目標（手取り） | 必要な売上 | 届くための形 |
|---|---|---|
| 月 10 万円 | 約 12.1 万円 | 単品の有料記事の積み上げで届く |
| 月 15 万円 | 約 18.2 万円 | メンバーシップで固定収入の土台を作り、単品を上に乗せる |
| 月 30 万円 | 約 36.3 万円 | 高単価商品か会員数が要る。note の外からの流入が前提 |
| 月 50 万円 | 約 60.4 万円 | note は入口。本業や講座など単価の高いものに繋ぐ形 |

**目標の額で、AI に渡す設計の指針が切り替わります。** 月 50 万円のときに
「有料記事を大量に書けば届く」という計画を書かせないためです。
使える時間で届かない目標なら、届かないと明記させます。

実績も手取りで見ます。振込の実額を入れればそれを使い、売上しか入れていなければ手数料を引いた概算で計算します。

手数料率は変わりうるので概算として扱い、画面にもその断りを出しています。
率が変わったら `lib/revenue.ts` の `FEES` を直せば全体に反映されます。

### 算数をサーバー側でも検算する

計画の「単価 × 本数 = 小計」「小計の合計 ≧ **必要な売上**」「週の作業時間 ≦ 使える時間」は、
AI の出力を信じずサーバー側で計算し直します。合わなければ画面に警告が出ます
（`app/api/steps/plan/route.ts`）。

必要な売上もサーバー側で確定させます。AI が手取りの額をそのまま売上として組んでしまうと、
計画どおり売れても手数料のぶん目標に届かないためです。

### 有料記事の形を強制する

- 無料部分が全体の 35% を切ったら警告（買う判断ができず売れないため）
- 有料部分が 1,500 文字未満なら警告
- AI が埋められなかった一次情報は `fillIns` として別枠に出し、本文には【 】で残す

### 顧客情報を端末に置かない

案件のデータ（リサーチ結果・戦略・記事・売上）はすべて共有データベースに置きます。
`localStorage` は使いません。書き出しは管理者だけができ、誰がいつ何件書き出したかが記録に残ります。

## 使いはじめる

### 1. 設定ファイルを作る

**`.env` は GitHub にはありません。手元で作るファイルです。**

API キーとパスワードが入るので、`.gitignore` で除外してあります
（git に入れると、リポジトリを見られる全員に鍵が渡ってしまうため）。
GitHub にあるのは中身が空の見本（`.env.example`）だけです。

このフォルダで、見本をコピーして作ってください。

```
cd note-studio
cp .env.example .env      # Windows のコマンドプロンプトなら  copy .env.example .env
```

できた `.env` をテキストエディタで開いて、次を埋めます。

| 変数 | 何に使うか |
|---|---|
| `ANTHROPIC_API_KEY` | リサーチの分析・記事の執筆（必須） |
| `APP_PASSWORD` | ログインの署名の鍵（必須。本番で未設定だと誰も入れません） |
| `DATABASE_URL` | アカウントと案件データの置き場（必須。Neon を想定） |

`.env` は git に入らないので、そのまま置いておいて問題ありません。

### 2. 起動

```
npm install
npm run dev
```

http://localhost:3003 が開きます。

### 3. 最初の管理者を作る

初回はログイン画面が「最初の管理者を作る」に変わります。
お名前・パスワード（12文字以上）・`APP_PASSWORD` の値を入れると、管理者アカウントができます。
以降のアカウントは `/admin` から発行します。

### 4. 公開する

Vercel に載せる場合、`.env` はアップロードされません（git に入っていないため）。
Vercel の Environment Variables に `ANTHROPIC_API_KEY` / `APP_PASSWORD` / `DATABASE_URL` を
入れてから Redeploy してください。入れ忘れると本番で誰もログインできません（素通しにはなりません）。

## note からのデータ取得について

note の公開ページが使っている JSON エンドポイントを読んでいます。**公開 API ではありません。**

- ログイン不要で、誰でも見られる情報しか取りません（記事タイトル・価格・スキ数・投稿日など）
- 1 回ごとに間隔を空け（既定 700ms）、1 リサーチあたりの回数にも上限（既定 40 回）があります
- note 側の都合で形が変わりうるため、複数のエンドポイントを順に試し、
  応答の形を決め打ちせずに「記事らしいオブジェクト」を探して拾う実装にしています

**取得できなくなったときは、「② 競合リサーチ」の「note との接続を確認」を押してください。**
いま実際に何が返っているか（ステータス・件数・生のデータ）が見えます。
403 や 404 が並ぶ場合は note 側の仕様が変わった可能性が高く、
`lib/note-api.ts` の `searchNotes()` にあるエンドポイント候補を足せば直せます。

## ファイルの地図

```
lib/note-api.ts    note の公開データを読む（エンドポイント候補・正規化・レート制限）
lib/research.ts    取ってきた記事から数字を出す（価格分布・スキ・投稿間隔・頻出語）
lib/prompts.ts     AI への指示。ツールの品質はほぼここで決まる
lib/schemas.ts     AI に返させる JSON の形。lib/types.ts と 1 対 1
lib/claude.ts      AI 呼び出しの共通部分
lib/revenue.ts     手数料の計算と、目標の段階ごとの設計指針
lib/store.ts       案件の保管（共有データベース）
lib/article.ts     記事を note に貼れる形にする

app/api/steps/*    6 工程それぞれの生成 API
app/api/note/diagnose  note との接続確認
app/api/admin/export   書き出し（管理者だけ・記録に残る）

components/Workspace.tsx  案件の作業場（タブ）
components/steps/*        各工程の画面
```

ログイン一式（`lib/users.ts` `lib/auth.ts` `lib/auth-edge.ts` `lib/rate-limit.ts` `middleware.ts` ほか）は
`insta-studio/` と同じものです。Cookie 名は `note_session`、テーブルの接頭辞は `note_` です。
