## Indeed APIのレート制限について（最重要）

アカウント単位のクォータがあり、使い切ると1件ずつでも通らなくなります。

**リトライ自体が枠を消費します。** 失敗したら必ず待ってください。連打すると
待ち時間が16秒→40秒と伸びていきます。**短い待機を繰り返すより、10〜15分まとめて
待ってから1本投げて回復を確認する**ほうが確実です。回復後は1ラウンド1〜2クエリで、
ラウンドごとに必ず `raw-postings.tsv` への保存を挟んでください。

**保存を飛ばさないこと。** 検索結果を保存する前に次の検索へ進むと、レート制限に
当たった時点で取得済みの結果が失われます。実際に一度失っています。

### 収集時の注意（実際に踏んだ落とし穴）

- **本部（フランチャイザー）にブランド列を入れないこと。** 例えば「ほっともっと」で
  検索すると本部の株式会社プレナスも出てきますが、ここにブランド列を入れると
  社名にブランド名が含まれないためFCと誤判定されます。本部は空欄にしてください
- **求人タイトルを必ず見ること。** ブランド名がタイトルに無い求人（例:
  フレッシュフーズファクトリーの「第二新卒・既卒/ 店舗スタッフ」）は、
  ブランド検索で出てきてもFCとは断定できません。空欄にしてください
- **明光義塾のような「ブランド名＝社名」のケースはFC判定が付きません。** これは
  正しい挙動です。運営会社が特定できないため、「運営元の法人名を要確認」フラグを
  頼りに個別に調べる運用になります

## 作業手順

```bash
node sales/indeed/scripts/build-list.mjs      # 集計（重複は自動で除外され警告が出る）
node sales/indeed/scripts/build-console.mjs   # コンソール生成（2種類出力）
```

そのあと `console.artifact.html` を同じArtifact URLへ再公開する:
https://claude.ai/code/artifact/251ee0c7-846d-476e-8edc-934f496e2ef1

**再公開の手順**: 別セッションが公開ページを触っている場合、いきなり publish すると
409で弾かれます。その場合は WebFetch で公開ページを読んでから publish し直してください
（force での上書きはしないこと）。公開ページを直接編集した変更は次のビルドで消えるため、
恒久的な変更は必ず生成スクリプト側に入れてください。
