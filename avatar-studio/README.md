# アバタースタジオ

「SNSで発信したいが、毎回撮影する時間がなく顔出しも避けたい」という経営者・専門家向けに、**本人のAIアバターで顔出しなしにショート動画を回し続ける運用**を設計するアプリです。TikTok / Instagramリール / YouTubeショートに対応し、そのまま月額の運用代行として売るための料金プランまで出力します。

このフォルダは**単体で動く独立したアプリ**です。同じリポジトリにある Indeed 提案スタジオ・Insta Studio とはコードを一切共有していません。ポートも 3001 で分けてあるため、両方を同時に起動できます。

---

## 核となる考え方 — ボトルネックを「撮影」から「何を言うか」に移す

発信が続かない理由は「ネタがない」ではなく、撮影という作業が重いことです。髪を整え、服を選び、場所を確保し、噛んだら撮り直す。1本のために30〜60分が消え、ほぼ全員が3週目で止まります。

アバターを一度作ってしまえば、以後は**テキストの台本を書くだけ**で動画になります。だからこのアプリの重心は、アバターの生成そのものではなく **台本・投稿設計・導線設計** に置いています。動画にするだけの作業はツール側が年々簡単にしていて、それ自体はもう売り物にならないためです。

AIアバター動画が伸びない原因は決まっているので、設計段階で潰します。

- 冒頭がアバターの顔で始まる → 冒頭2秒は実写素材かテロップ全画面にし、アバターは3秒目以降に出す
- 一本調子で情報密度が低い → 1文を短く切り、同じ構図を5秒以上続けない
- 表情と身振りが動かない → 台本側で表情の変えどころ・うなずき・間を指定する
- 音声だけで理解させようとする → テロップだけで意味が通るように書く
- 毎回違う人物に見える → 服装・背景・声・名乗りを固定する
- AIであることを隠す → 隠すと信用を失う。先に開示し、「顔を出さない理由」自体をコンテンツにする

## 出力される設計

| タブ | 内容 |
|---|---|
| **① アバター設計** | 現状分析(発信が止まる構造・よくある失敗) / アバターの見た目・声・話し方・毎回固定する決めごと / 使うツールと初回セットアップ手順 / アバター画像生成プロンプト(OpenAI APIキー設定時は画像も生成) / 届ける相手 / コンテンツの柱と割合 / フック集10〜12本 |
| **② 台本** | 完成台本5本。フック(0〜2秒) → 本編4〜6ビート → 締めまで、読み上げ原稿・テロップ・映像指示・演出指示・離脱対策・キャプション・ハッシュタグ・カバー文字つき。「読み上げ原稿」はアバターツールにそのまま貼れます。**「さらに5本つくる」で、同じアバター・同じ柱のまま別テーマの台本を追加できます** |
| **③ 量産オペ** | 制作フロー(誰が・何分で・どのツールで) / 1本あたりの制作時間と週の回し方 / 使うツールと料金の目安 / まとめ量産のコツ / 最初の30日の投稿カレンダー12〜16本 / 導線設計 / KPI / 他媒体への横展開 |
| **④ 収益設計** | 何を売っているのかの定義 / 料金プラン3段階(月額・含まれるもの・納品物・提供側の原価と工数) / 契約から初回投稿までの手順 / 継続してもらう仕組み / アップセル / 商談で出る反論と切り返し / 法令・規約上の注意点 / 初月30日のチェックリスト |

設計書全体は Markdown で、台本は .txt でコピー・ダウンロードできます。

## ヒアリング項目

**★印の項目が台本の質を決めます。** 台本の材料は本人の頭の中にしかないためです。

- 発信の目的(集客 / 商品販売 / 権威づけ / 採用)・主戦場・顔出しの方針(本人そっくり / 別人 / 声だけ本人)
- 基本情報 — 企業名 / サイトURL(内容を自動で読み取ります) / 事業内容 / 商材・価格
- **★ 台本の材料** — 本人が普段お客様に話していること・語り口 / よく聞かれる質問 / 届けたい相手 / 実績・数字
- 発信者とアバター — プロフィール / 希望する見た目・声 / 使える素材
- 現状と制約 — これまでの発信状況と続かなかった理由 / 参考アカウント / NG表現 / 投稿本数・体制 / 予算
- 本人・商品・現場の写真(最大3枚・任意) — アバターの設計とBロールの指示に反映します

**ヒアリングに無い数字・実績・事例は台本にも書きません。** 素材が無いテーマは、条件付きの一般論に落とすか、企画自体を差し替えます。

フォーム下部の「サンプル(外壁塗装会社)を入力してみる」で、典型例をそのまま試せます。

# セットアップ

```bash
# 1. このフォルダに移動
cd avatar-studio

# 2. 依存関係のインストール
npm install

# 3. 環境変数の設定
#    .env.example を .env という名前でコピーし、APIキーを設定する
#    ANTHROPIC_API_KEY=sk-ant-...  (必須)
#    OPENAI_API_KEY=sk-...          (任意: アバターの見た目案を画像で出す場合)

# 4. 起動
npm run dev
```

- http://localhost:3001 — アバタースタジオ

## Windows でダブルクリック起動する

初回のセットアップ(`npm install` と `.env` の作成)が済んでいれば、以降は **`start-avatar.bat` をダブルクリック**するだけです。ブラウザが自動でアバタースタジオを開きます。

黒い画面が出たままになりますが、**これがサーバー本体**なので開いたままにしてください。閉じるとアプリが止まります。

デスクトップにショートカットを作るには、`start-avatar.bat` を右クリック →「送る」→「デスクトップ (ショートカットを作成)」。

**ポート3001を使うため、隣のフォルダのアプリ(ポート3000)と同時に起動できます。**

## チームで使う(1台を社内で共有する)

**`start-avatar-shared.bat` をダブルクリック**すると、同じ社内ネットワークにいる人が自分のブラウザから使えるようになります。起動時に、伝えるべきURL(`http://192.168.x.x:3001`)が黒い画面に表示されます。

社外に公開する場合は、`.env` に `BASIC_AUTH_USER` と `BASIC_AUTH_PASSWORD` を必ず設定してください。未設定だとURLを知った人が誰でもアクセスでき、APIの利用料が発生します。

## Vercel に公開する

このフォルダを **別プロジェクト**としてデプロイします(リポジトリ直下のアプリとは別のURLになります)。

1. Vercel(https://vercel.com/dashboard)で **Add New… → Project**
2. このリポジトリを **Import**
3. **Root Directory** に **`avatar-studio`** を指定
4. **Environment Variables** を設定

| 変数 | 要否 |
|---|---|
| `ANTHROPIC_API_KEY` | 必須 |
| `BASIC_AUTH_PASSWORD`(と任意で `BASIC_AUTH_USER`) | 公開URLで使うなら実質必須。未設定だと誰でもアクセスでき、API利用料が発生します |
| `ANTHROPIC_MODEL` | 任意(既定は `claude-opus-5`) |
| `OPENAI_API_KEY` / `OPENAI_IMAGE_MODEL` | 任意(アバターの見た目案を画像で出す場合のみ) |

5. **Deploy**

`vercel.json` に `"framework": "nextjs"` を入れてあるため、Framework Preset が `Other` のままプロジェクトが作られても Next.js アプリとしてビルドされます(この指定が無いと `No Output Directory named "public" found` で失敗します)。

生成は1段階あたり最大5分かかることがあります。実行時間の上限が60秒のプランでは途中で切れるため、上限を延ばせるプランが必要です。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| `[ERROR] .env not found` | `.env.example` を `.env` にコピーし、`ANTHROPIC_API_KEY` を設定 |
| `[ERROR] Port 3001 is already in use` | すでにアバタースタジオの黒い画面が開いています。閉じてから起動し直す |
| ブラウザが404を出す | URLが `http://localhost:3001` になっているか確認(3000は別のアプリです) |
| Vercelで `No Output Directory named "public" found` | Vercelがこのアプリを Next.js と認識していません。`vercel.json` がある状態で Redeploy するか、Vercelの Settings → Build and Deployment → Framework Preset を `Next.js` に変更 |
| 「APIキーが無効です」 | `.env` の `ANTHROPIC_API_KEY` を確認。行末の空白や引用符に注意 |
| 生成が途中で止まる | 段階ごとに再試行できます。ヒアリング内容を少し減らすと通ることがあります |

# 運用前に必ず確認すること

生成結果の④タブに案件ごとの注意点が出ますが、共通して次の4点は契約前に押さえてください。

1. **本人の肖像・声をAIで再現する場合**、書面での同意と利用範囲(媒体・期間・解約後のモデル削除)の取り決めが必要です
2. **各プラットフォームのAI生成コンテンツの表示ルール**に従い、プロフィールと動画内で開示します
3. **景品表示法(優良誤認・No.1表示)とステマ規制** — 対価を受けた紹介には「広告」「PR」を明示します
4. **業種特有の法規制** — 医療・美容・健康食品(薬機法)、金融、士業などは断定表現を使いません

# 技術構成

- [Next.js 15](https://nextjs.org/) (App Router) + TypeScript + React 19
- [Anthropic TypeScript SDK](https://github.com/anthropics/anthropic-sdk-typescript) — 構造化出力 (JSON Schema) で設計を生成
- OpenAI Images API — アバターの見た目案(任意)

## 生成の流れ

1回のリクエストが長すぎるとブラウザや中継サーバーが接続を切るため、段階ごとに別のリクエストに分けています。応答は NDJSON のストリームで、進捗と ping を流し続けて接続を保ちます。

```
①a 発信の型 / ①b アバターの設定   (どちらもヒアリング内容だけから決まるので並列)
          ↓
②台本 / ③量産オペ / ④収益設計      (①の結果を受けて並列)
```

段階を分けているのは接続時間の対策だけでなく、構造化出力のスキーマが大きすぎると文法をコンパイルできない (`compiled grammar is too large`) という制約もあるためです。
